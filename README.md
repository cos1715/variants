# Варіанти — MVP, етап 2

Мобільна браузерна party game українською. Реалізовано створення й приєднання до кімнати, список учасників у реальному часі, публічну бібліотеку пресетів і безпечну фіксацію питань під час старту гри.

## Запуск

1. Скопіюйте `.env.example` у `.env.local` і вкажіть значення зі свого Supabase-проєкту.
2. У Supabase відкрийте **SQL Editor** та послідовно виконайте міграції з `supabase/migrations/`. Для нового проєкту почніть з `202610210001_create_rooms_and_participants.sql`, а потім застосуйте `20261021091330_room_preset_and_end_state.sql`, `20261021112648_presets_and_room_questions.sql` і `20261021113351_fix_question_ordering.sql`.
3. У **Project Settings → API → Data API** додайте до exposed tables: `rooms`, `participants`, `room_lobby_events`. Це не відкриває приватні таблиці для браузера: RLS і SQL-міграція забороняють доступ `anon`/`authenticated` до `rooms` та `participants`.
4. Встановіть залежності та запустіть застосунок:

```bash
npm install
npm run dev
```

Відкрийте `http://localhost:3000`.

## Змінні середовища

| Змінна | Де використовується |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | браузер і сервер; URL проєкту |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | браузер; лише підписка на безпечні lobby-події |
| `SUPABASE_SERVICE_ROLE_KEY` | лише Next.js-сервер; створення та читання приватних записів |

Ніколи не додавайте `SUPABASE_SERVICE_ROLE_KEY` до змінних із префіксом `NEXT_PUBLIC_`.

## Модель безпеки

- Ведучий отримує випадковий 256-бітний токен. У базі є тільки SHA-256 хеш; сам токен зберігається у `HttpOnly` cookie.
- Кожен учасник отримує власний випадковий токен також лише в `HttpOnly` cookie. Саме він дає доступ до кімнати після оновлення сторінки.
- API перевіряє токен перед поверненням стану кімнати. Старт гри додатково вимагає токен ведучого — прихована кнопка не дає прав.
- Браузер не має прямого доступу на запис до таблиць Supabase. Публічна бібліотека працює через серверні API з перевіркою полів і лімітом тіла запиту.
- Питання активної гри з правильними відповідями копіюються в `room_questions` лише на сервері. `anon` не має прав читати цю таблицю або викликати процедуру створення snapshot.
- Для Realtime відкрито тільки читання таблиці подій без імен, відповідей або токенів; детальний список повертає сервер після перевірки cookie.
